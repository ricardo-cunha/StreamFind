## Fixture Findings

### `260115_ADC.txt`

Shimadzu LCsolution LC-UV/analog chromatogram export.

Required behavior:

- Detect as `ShimadzuTXT`.
- Parse `[LC Chromatogram(...)]` blocks.
- Support detector/channel labels such as `Detector A-Ch1` and `AD1`.
- Parse block metadata: `Interval(msec)`, `# of Points`, `Start Time(min)`, `End Time(min)`, `Intensity Units`, `Intensity Multiplier`, and optional `Wavelength(nm)`.
- Parse table columns beginning with `R.Time (min)` and `Intensity`.
- Return chromatogram arrays as time in minutes and scaled intensity.

### `karl.txt`

Shimadzu LabSolutions LC-MS chromatogram export, not just another UV TXT fixture.

Required behavior:

- Detect as `ShimadzuTXT`.
- Parse repeated `[MS Chromatogram]` sections.
- Support labels on the following `m/z` line, for example `1-1MS(E+) TIC` and MRM-style labels.
- Parse `# of Points`, `Start Time(min)`, `End Time(min)`, and data columns `R.Time(min)`, `Absolute Intensity`, `Relative Intensity`.
- Use `Absolute Intensity` as the returned intensity array.
- Keep `Relative Intensity` out of the returned arrays for the first implementation. It can be added later if an API shape for auxiliary arrays is introduced.

### `karl.mzML`

Reference file for the existing mzML backend.

Required behavior:

- Existing mzML reading must continue to work.
- Compare `karl.txt` with `karl.mzML` only at a coarse level: detected format, chromatogram count, retention time ranges, first headers, and TIC-like traces if available.
- Do not require exact one-to-one equivalence because exported TXT may contain processed or export-selected traces.

### `.lcd` Files

Initial behavior:

- Detect OLE Compound File signature bytes `D0 CF 11 E0 A1 B1 1A E1`.
- Return/detect format as `ShimadzuLCD`.
- Throw this explicit message when a reader is created:

```text
Shimadzu LCD detected, but native LCD chromatogram decoding is not implemented yet. Export to TXT or ASC for now.
```

- Do not silently return empty data.

Add fields:

Implementation details:

- Keep MS-specific fields for UV/ASC rows, setting `polarity = 0`, `precursor_mz = NaN`, `activation_ce = NaN`, and `product_mz = NaN`.
- Existing mzML chromatogram headers should populate new fields with sensible defaults: `signal_type = "MS"`, `chromatogram_type` inferred from id/CV terms where available, `detector = "MS"`, `units = "counts"` if no better value exists.

## Format Detection

Extend `MS_FILE::possible_formats` to include:

```cpp
{"mzML", "mzXML", "ShimadzuTXT", "ASC", "ShimadzuLCD"}
```

Detection priority in `detect_format()`:

1. `.mzML` or `.mzml` returns `mzML`.
2. `.mzXML` or `.mzxml` returns `mzXML`.
3. `.lcd` with the OLE signature returns `ShimadzuLCD`.
4. `.txt` containing `[LC Chromatogram(` or `[MS Chromatogram]` returns `ShimadzuTXT`.
5. `.asc` returns `ASC`.
6. Otherwise throw the existing unsupported-format style error.

For TXT detection, scan only an initial chunk large enough to include the header and first chromatogram section, then fall back to a fuller scan if needed. This avoids loading very large exports unnecessarily during detection.

## TXT Reader

Add `shimadzu_txt::Reader` in `reader.h` and implement it in `reader.cpp`.

### Internal Representation

Use a small internal record for parsed chromatograms. Store scalar metadata per block, then build the vectorized `MS_CHROMATOGRAMS_HEADERS` result in `get_chromatograms_headers()`:

```cpp
struct ChromatogramBlock {
  int index = 0;
  std::string id;
  std::string signal_type;
  std::string chromatogram_type;
  std::string detector;
  std::string channel;
  std::string units;
  int polarity = 0;
  float precursor_mz = std::numeric_limits<float>::quiet_NaN();
  float activation_ce = std::numeric_limits<float>::quiet_NaN();
  float product_mz = std::numeric_limits<float>::quiet_NaN();
  float wavelength_nm = std::numeric_limits<float>::quiet_NaN();
  float interval_ms = std::numeric_limits<float>::quiet_NaN();
  float start_time = std::numeric_limits<float>::quiet_NaN();
  float end_time = std::numeric_limits<float>::quiet_NaN();
  float intensity_multiplier = 1.0f;
  std::vector<float> time;
  std::vector<float> intensity;
};
```

The actual implementation can avoid this exact type if simpler, but keep parsed scalar metadata next to arrays and convert it to the public vectorized header structure at the API boundary.

### Shared Parsing Utilities

Add private/local helpers in `reader.cpp`:

- trim whitespace and `\r`.
- split tab-delimited metadata rows.
- parse float with empty-value handling.
- parse positive/negative polarity from `E+` and `E-`.
- classify MS trace label as `TIC`, `MRM`, `XIC`, or `MS Chromatogram`.
- parse MRM transition from labels containing `precursor>product`, storing `precursor_mz` and `product_mz` when available.

### LC Block Rules

For each `[LC Chromatogram(name)]` block:

- `id`: full block name.
- `signal_type`: `UV` if wavelength is present or detector label suggests optical trace, otherwise `Analog` for `AD` style labels.
- `chromatogram_type`: `UV Trace` or `Analog Trace`.
- `detector`: parsed detector part, for example `Detector A`.
- `channel`: parsed channel part, for example `Ch1` or `AD1`.
- `units`: `Intensity Units`.
- `wavelength_nm`: `Wavelength(nm)` or NaN.
- `interval_ms`: `Interval(msec)` or inferred from time deltas.
- `start_time` and `end_time`: metadata values, or array min/max if absent.
- `intensity_multiplier`: metadata value, default `1.0`.
- Returned intensity: `raw_intensity * intensity_multiplier`.

Validate `# of Points` against parsed row count. Do not fail for a mismatch unless the block has no data; instead keep the parsed data and make the mismatch easy to see in the dev inspection script.

### MS Block Rules

For each `[MS Chromatogram]` block:

- Read the next `m/z` metadata line as the trace label.
- `id`: trace label.
- `signal_type`: `MS`.
- `chromatogram_type`: `TIC`, `MRM`, `XIC`, or `MS Chromatogram`.
- `detector`: `MS`.
- `channel`: full trace label.
- `units`: `counts`.
- `polarity`: `1` for `E+`, `-1` for `E-`, `0` if absent.
- `precursor_mz` and `product_mz`: parsed from transition labels when available, otherwise NaN.
- `start_time` and `end_time`: metadata values, or array min/max if absent.
- Returned intensity: `Absolute Intensity`.

Ignore `Relative Intensity` for the first implementation.

### Reader Defaults

For chromatogram-only TXT files:

- `get_number_spectra()` returns `0`.
- `get_number_chromatograms()` returns parsed chromatogram count.
- `get_number_spectra_binary_arrays()` returns `0`.
- `get_format()` returns `ShimadzuTXT`.
- `get_type()` returns `chromatogram`.
- `get_start_rt()` and `get_end_rt()` return min/max chromatogram time across parsed blocks, or `0.0f` when no data exists.
- Spectra methods return empty/default values and must not throw just because the file is chromatogram-only.

## ASC Reader

Add `asc::Reader` as a generic two-column chromatogram reader after TXT works.

Parsing rules:

- Ignore empty lines.
- Ignore comment/header lines starting with `#`, `[`, or non-numeric text.
- Detect delimiter in this order: tab, comma, semicolon, whitespace.
- Parse the first two numeric columns as time and intensity.
- Treat time as minutes by default.
- Do not auto-convert seconds purely because values are large. Only convert if a header explicitly says seconds.

Header defaults:

```cpp
signal_type = "Unknown";
chromatogram_type = "Chromatogram";
detector = "";
channel = "";
units = "";
wavelength_nm = NaN;
interval_ms = inferred median diff * 60000 when time is minutes;
intensity_multiplier = 1.0;
```

## Implementation Order

1. Extend chromatogram metadata structs and default population for existing mzML/mzXML readers.
2. Extend format detection and `create_reader()` with `ShimadzuTXT`, `ASC`, and `ShimadzuLCD`.
3. Implement `shimadzu_txt::Reader` for `[LC Chromatogram(...)]` and `[MS Chromatogram]` sections.
4. Run `devtools::load_all()` and `dev/dev_reader/inspect_reader.R` against TXT and mzML fixtures.
5. Update project storage structs, DuckDB schema validation, cache serialization, and R data frame conversion.
6. Verify `ProjectMassSpec` accepts chromatogram-only TXT files and exposes chromatogram headers/data.
7. Implement `asc::Reader` and add it to the inspection script.
8. Implement LCD detection and explicit unsupported reader stub.
9. Run `compare_txt_mzml.R` and `inspect_lcd_signature.R`.
10. Run `devtools::document()` only if Rcpp exports or documentation changed.

## Acceptance Criteria

The work is complete when:

- Existing mzML/mzXML behavior still works after `devtools::load_all()`.
- `260115_ADC.txt` reads as chromatogram-only data with LC/UV or analog metadata.
- `karl.txt` reads `[MS Chromatogram]` blocks with absolute intensity arrays.
- `karl.mzML` still reads through the existing mzML backend.
- `.lcd` files are detected and fail with the explicit unsupported-native-decoding message.
- `ProjectMassSpec` accepts TXT/ASC/mzML/mzXML files and treats TXT/ASC as valid chromatogram-only analyses.
- `ProjectMassSpecChromatograms` can display and retrieve chromatograms from LC UV/AD TXT exports and MS TXT/mzML chromatograms.
- New chromatogram header metadata is visible from the R data frame returned by `rcpp_project_mass_spec_get_chromatograms_headers()`.

## Non-Goals For First Pass

- Native LCD stream decoding.
- Storing `Relative Intensity` from Shimadzu MS TXT exports.
- Exact TXT-to-mzML equivalence for `karl`.
- Moving vendor fixture files into package tests.
- Changing the public chromatogram array shape.
