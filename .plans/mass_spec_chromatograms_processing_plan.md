## 1. Goal

Add staged development support in:

```text

```

and implement a chromatogram-processing method layer for:

```text
R/class_ProjectMassSpecChromatograms.R
R/class_MethodsMassSpecChromatograms.R
src/core/mass_spec/processing.h
src/core/mass_spec/processing.cpp
src/rcpp_project_export.cpp
```

The objective is to make chromatograms from mass spectrometry files available as project-level processable data in DuckDB.

The first two processing methods are:

1. `LoadChromatograms`
   - Select raw chromatograms by regular-expression rules applied to the chromatogram id/name.
   - Load matching chromatogram traces from the already registered mass-spec analyses/files.
   - Persist the selected traces into a DuckDB table named `MS_CHROMATOGRAMS`.

2. `FilterChromatogramsRetentionTime`
   - Read chromatograms already persisted in `MS_CHROMATOGRAMS`.
   - Keep only points within a retention-time interval.
   - Replace the chromatograms in `MS_CHROMATOGRAMS` with the filtered result.

The implementation should follow the existing processing-method style used by `NonTargetAnalysis`, while keeping the chromatogram backend in `src/core/mass_spec`. Also, the processing methods should use the same cache framework to load processed chromatograms when the method is applied again with the same conditions as implemented for the nta methods.

## 2. Design Principles

### 2.1 Keep Raw Data and Processed Data Separate

Raw chromatograms are available from source files through the existing mass-spec reader layer.

`LoadChromatograms` should not import new analyses. It should:

1. inspect raw chromatogram metadata,
2. match chromatogram ids by regex,
3. load only matching traces,
4. persist them as project-managed chromatogram records.

### 2.2 Processed Chromatograms Replace the Chromatograms

`MS_CHROMATOGRAMS` holds one set of chromatogram trace points per `(project_id, analysis, index)`.

Processing methods do not create new staged copies. They read the existing rows, apply the transformation, and replace the rows in-place.

- `LoadChromatograms` inserts new rows. `raw_intensity` is set from the source file. `intensity` is initialized to `raw_intensity`. `baseline` is initialized to `0`.
- `FilterChromatogramsRetentionTime` removes points outside the RT window and updates `intensity` accordingly. The `raw_intensity` column is preserved unchanged.
- Future methods (e.g. baseline correction) update `baseline` and/or `intensity` while keeping `raw_intensity` intact.

Do not add compatibility fallbacks for previous table layouts. This phase targets the current schema only.

### 2.3 Make Processing Reproducible

Every persisted chromatogram point contains enough metadata to identify:

- project,
- analysis,
- chromatogram index,
- source chromatogram id,
- retention time,
- raw intensity,
- baseline,
- processed intensity,
- creation timestamp.

### 2.4 Follow Existing Method Conventions

Each method should have:

- a method constructor,
- a validator,
- a `run.<MethodClass>()` S3 method,
- a native Rcpp function,
- a C++ backend implementation.

Use the same style as `R/class_MethodsNonTargetAnalysis.R` where practical.

## 4. DuckDB Table: `MS_CHROMATOGRAMS`

### 4.1 Table Purpose

`MS_CHROMATOGRAMS` stores processable chromatogram trace points.

Each row represents one chromatogram data point.

### 4.2 Columns

| Column | Type | Required | Description |
|---|---:|---:|---|
| `project_id` | `TEXT` | yes | Project identifier. |
| `analysis` | `TEXT` | yes | Analysis name. |
| `chromatogram_id` | `TEXT` | yes | Original chromatogram id/name from raw file. |
| `rt` | `DOUBLE` | yes | Retention time. Use seconds unless the current codebase already standardizes another unit. |
| `raw_intensity` | `DOUBLE` | yes | Raw intensity as in the original file |
| `baseline` | `DOUBLE` | yes | Baseline of the chromatogram intensity when applied by the dedicated method, init empty or 0. |
| `intensity` | `DOUBLE` | yes | Processed intensity. |
| `created_at` | `TIMESTAMP` | yes | Processing timestamp. |

Primary key: `PRIMARY KEY(project_id, analysis, chromatogram_id, rt)`.

### 4.3 Replacement Strategy

Processing methods replace the chromatogram rows in-place.

`LoadChromatograms` inserts new rows for each matched chromatogram. If the same `(project_id, analysis, chromatogram_id)` already exists, the existing rows are deleted first and new rows are inserted.

`FilterChromatogramsRetentionTime` reads the existing rows for the selected analyses, keeps only points where `rt >= rtmin AND rt <= rtmax`, deletes the old rows for those chromatograms, and inserts the filtered rows back. The `raw_intensity` column is preserved unchanged. The `intensity` column is carried over from the previous state.

### 4.4 Indexes

Add indexes only if the existing project database helper has a standard place for this. Recommended indexes:

```sql
CREATE INDEX IF NOT EXISTS idx_ms_chrom_project_analysis
ON MS_CHROMATOGRAMS(project_id, analysis);

CREATE INDEX IF NOT EXISTS idx_ms_chrom_rt
ON MS_CHROMATOGRAMS(project_id, analysis, rt);
```

### 5.3 Validation

Implement:

```r
validate_object.Method_MassSpecChromatograms_LoadChromatograms <- function(x, ...) {
  .validate_ms_chrom_method_base(
    x,
    "Method_MassSpecChromatograms_LoadChromatograms",
    "LoadChromatograms",
    number_permitted = 1
  )

  checkmate::assert_character(x$parameters$chromatogramIdRegex, min.len = 1, any.missing = FALSE)
  checkmate::assert_logical(x$parameters$ignoreCase, len = 1, any.missing = FALSE)
  checkmate::assert_logical(x$parameters$invert, len = 1, any.missing = FALSE)

  invisible(NULL)
}
```

### 5.4 Run Method

Add:

```r
run.Method_MassSpecChromatograms_LoadChromatograms <- function(x, proj, ...) {
  checkmate::assert_class(x, "Method_MassSpecChromatograms_LoadChromatograms")
  validate_object(x)
  checkmate::assert_class(proj, "ProjectMassSpecChromatograms")

  params <- x$parameters

  success <- rcpp_project_mass_spec_chromatograms_load(
    chromatograms_xptr = proj$get_mass_spec_chromatograms_ptr(),
    analyses = character(),
    chromatogramIdRegex = as.character(params$chromatogramIdRegex),
    ignoreCase = isTRUE(params$ignoreCase),
    invert = isTRUE(params$invert)
  )

  .run_ms_chrom_method(success, proj, "Loading chromatograms did not complete successfully.")
}
```

### 5.5 Native Behavior

The backend should:

1. resolve selected analyses;
2. get chromatogram headers for each analysis;
3. match `id` against the provided regex vector;
4. load trace arrays for each selected chromatogram;
5. assign a stable `index` per chromatogram within each analysis;
6. for each trace point, write a row to `MS_CHROMATOGRAMS` with:
   - `raw_intensity` from the source file,
   - `intensity` initialized to `raw_intensity`,
   - `baseline` initialized to `0`,
   - `created_at` set to the current timestamp;
7. if a row with the same `(project_id, analysis, index)` already exists, delete it before inserting;
8. return `true` if completed.

### 5.6 Regex Matching Semantics

If multiple regex patterns are supplied, match when any pattern matches:

```text
match = regex_1 OR regex_2 OR ... OR regex_n
```

If `invert = TRUE`, keep chromatograms where `match == FALSE`.

Use `std::regex` in C++ or existing project regex helpers if available.

### 6.4 Run Method

Add:

```r
run.Method_MassSpecChromatograms_FilterChromatogramsRetentionTime <- function(x, proj, ...) {
  checkmate::assert_class(x, "Method_MassSpecChromatograms_FilterChromatogramsRetentionTime")
  validate_object(x)
  checkmate::assert_class(proj, "ProjectMassSpecChromatograms")

  params <- x$parameters

  success <- rcpp_project_mass_spec_chromatograms_filter_rt(
    chromatograms_xptr = proj$get_mass_spec_chromatograms_ptr(),
    analyses = character(),
    rtmin = as.numeric(params$rtmin),
    rtmax = as.numeric(params$rtmax)
  )

  .run_ms_chrom_method(success, proj, "Retention-time filtering of chromatograms did not complete successfully.")
}
```

### 6.5 Native Behavior

The backend should:

1. read all rows from `MS_CHROMATOGRAMS` matching:
   - `project_id`,
   - optional `analysis` filter;
2. group by `(project_id, analysis, index)`;
3. for each group, keep only rows where `rt >= rtmin AND rt <= rtmax`;
4. delete the old rows for the affected `(project_id, analysis, index)` values;
5. insert the filtered rows back, preserving `raw_intensity`, `baseline`, `intensity`, and `id`;
6. return `true`.

// [[Rcpp::export]]
bool rcpp_project_mass_spec_chromatograms_load_chromatograms(
    SEXP chromatograms_xptr,
    std::vector<std::string> analyses,
    std::vector<std::string> chromatogramIdRegex,
    bool ignoreCase = true,
    bool invert = false)

  return project::api::project_call([&]() {
    auto& chroms = project_mass_spec_chromatograms_from_xptr(chromatograms_xptr);

    mass_spec::processing::LOAD_CHROMATOGRAMS_REQUEST req;
    req.analyses = analyses;
    req.chromatogram_id_regex = chromatogramIdRegex;
    req.ignore_case = ignoreCase;
    req.invert = invert;

    return mass_spec::processing::load_chromatograms(chroms, req);
  });
}

bool rcpp_project_mass_spec_chromatograms_filter_retention_time(

## 13. Error Handling

### 13.1 `LoadChromatograms`

Stop with informative errors when:

- no analyses are available;
- selected analyses do not exist;
- no chromatogram headers are available;
- no chromatogram ids match the regex;
- a matching chromatogram has no trace points;
- DuckDB insert fails.

### 13.2 `FilterChromatogramsRetentionTime`

Stop with informative errors when:

- `rtmin >= rtmax`;
- no rows exist in `MS_CHROMATOGRAMS` for the selected analyses;
- no rows remain after filtering;
- DuckDB operation fails.
