📚
Training data Text, code, and examples are used to learn language patterns.
→
🧠
Language model Billions of learned parameters estimate what comes next.
The next token is...
→
💬

LLM = Large Language Model · It predicts the next likely token; it does not independently take actions.

What Is An AI Agent?

An AI agent is an autonomous system that uses an LLM to perceive, reason, and act within an environment.

LLMAI Agent
Stateless text completionStateful, goal-oriented
Single responseMulti-step reasoning
No tool accessCan use tools (search, code, APIs)
No memory of past turnsMaintains context & history
PassiveProactive - plans & executes

How An LLM Becomes An Agent

GoalUser request, constraints, and success criteria
→
LLM + orchestrationPrompting, planning, memory, tool selection, and the control loop
→
ActionTools execute work and return results for the next decision
OpenCodeLLM + filesystem, terminal, code search, and edit tools → coding agent

Claude CodeLLM + terminal, files, project instructions, and controlled execution → coding agent
VS Code / ContinueLLM + editor context, diagnostics, and code actions → IDE assistant

The same LLM can become very different agents: the platform determines its tools, permissions, memory, workflow, and feedback loop.

Model Properties: Size, Context, and More

ParametersMore parameters can represent more patterns and knowledge, but usually require more memory and compute.7B ≈ 7 billion weights; 70B ≈ 70 billion
Context windowHow much input and conversation the model can consider in one request.Examples: 4K, 8K, 32K, or 128K tokens
QuantizationWeights are stored with fewer bits, reducing memory use with a possible quality trade-off.Q8 = 8 bits/weight; FP16 = 16 bits/weight
VRAM / RAMModel weights, context cache, and runtime overhead must fit into available memory.7B FP16 ≈ 14 GB; 7B Q4 ≈ 4–5 GB
Latency and throughputLatency is time to respond; throughput is how many tokens or users the system can serve.Example: 20 tokens/s or 4 concurrent users
Training and specializationBase, instruct, reasoning, and coding models are optimized for different tasks.Examples: 7B instruct, 14B coding, 32B reasoning

→

→

Example: A filesystem MCP server exposes a read_file tool.

MCP Demonstration: The read_file Tool

// 1. MCP server backend (pseudocode)
registerTool("read_file", { path: "string" }, async ({ path }) => {
  const file = resolveAllowedPath(ALLOWED_ROOT, path);
  if (!file) throw new Error("Path is outside the allowed root");
  const text = await readTextFile(file);
  return { content: [{ type: "text", text }] };
});
// 2. Host configuration: start the server and scope its access
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["@modelcontextprotocol/server-filesystem", "./project"]
    }
  }
}
// 3. MCP server advertises the tool
{ "name": "read_file", "inputSchema": { "path": "string" } }
// 4. Agent host sends the tool call
{ "name": "read_file", "arguments": { "path": "./README.md" } }
// 5. Result returned to the LLM
{ "content": "...file text..." }

Agent Capabilities Depend On The Model And Runtime

💬
Text-onlyReads text and produces text. Tools can still let it act on files, code, and APIs.Example: Llama 3.1 8B, text in / text out
👁
VisionAccepts images and produces visual embeddings or classifications; it is not a conversational agent by itself.Example: ViT-B/16, image classifier
🎧
AudioProcesses speech or sound and produces a transcription or audio representation.Example: Whisper large-v3, audio in / text out
🔗
MultimodalAccepts more than one input type, such as text plus images, and can combine them in one response.Example: Qwen2.5-VL, text + image
“Agent” describes the orchestration and behavior, not a single model modality. A text model can be an agent; a vision model can be an agent; tools connect either one to the world.

What Is A Skill?

1. DiscoverThe host sees the skill name and description in its available skill catalog.
→
2. LoadWhen a request matches, the host loads the skill instructions and supporting resources.
→
3. ExecuteThe agent follows the workflow and uses its available tools to complete the task.
# Example: SKILL.md
name: rcpp-build
description: Build and update an R package with Rcpp C++ code

When changing Rcpp code:
1. Edit the C++ source files, not generated wrappers.
2. Run devtools::load_all() to compile and refresh exports.
3. Treat RcppExports.R as autogenerated; never edit it manually.
4. Run the package tests and report build errors.
Example: The user asks to update a C++ function. The agent loads rcpp-build, edits the C++ source, runs devtools::load_all(), and leaves RcppExports.R to the generation workflow.

Local Model Deployment

Why go local?

  • Data privacy - no data leaves your network
  • No API costs
  • Offline availability
  • Full control over model selection & configuration

Challenges:

  • Requires GPU hardware (or powerful CPU + quantization)
  • Setup and maintenance effort
  • Smaller model sizes vs cloud offerings

Option 1: Ollama

Ollama is the easiest way to run open-source LLMs locally.

FeatureDetails
InstallationOne-click installer for macOS, Linux, Windows
Model supportLlama 3, Mistral, Qwen, Gemma, Phi, DeepSeek, and 100+ more
QuantizationAutomatic - downloads GGUF quantized models
APIOpenAI-compatible REST API at localhost:11434
GPU supportCUDA (NVIDIA), Vulkan (AMD/Intel), Metal (Apple)
Use caseDevelopment, prototyping, single-user or small-team use
 
# Pull and run a model
ollama pull deepseek-r1:8b
ollama run deepseek-r1:8b

# API call (OpenAI-compatible)
curl http://localhost:11434/v1/chat/completions \
  -d '{"model":"deepseek-r1:8b","messages":[{"role":"user","content":"Hello"}]}'

Option 2: vLLM

vLLM is a high-throughput inference engine optimized for production.

FeatureDetails
Installationpip install vllm (Python package)
Model supportHugging Face models (Llama, Mistral, Qwen, etc.)
Key innovationPagedAttention - efficient KV cache management
Performance10-24x higher throughput than Hugging Face default
APIOpenAI-compatible server
GPU supportCUDA (NVIDIA only)
Use caseHigh-throughput production serving, multi-user
 
# Start the server
vllm serve mistralai/Mistral-7B-Instruct-v0.3 \
  --host 0.0.0.0 --port 8000

# API call
curl http://localhost:8000/v1/chat/completions \
  -d '{"model":"mistralai/Mistral-7B-Instruct-v0.3","messages":[{"role":"user","content":"Hello"}]}'

Option 3: ML Studio (Windows)

Windows ML Studio (part of Windows AI Studio / VS Code extension) simplifies running SLMs locally on Windows.

FeatureDetails
InstallationVia VS Code extension or Windows AI Dev Hub
Model supportPhi-3, Phi-3.5, Mistral, Llama (ONNX-optimized)
HardwareOptimized for Windows DirectML (AMD, Intel, NVIDIA)
IntegrationTight VS Code integration
Use caseWindows-native development, no Linux/WSL needed
ML Studio uses ONNX Runtime with DirectML, enabling GPU acceleration on any DirectX 12-compatible GPU - including AMD and Intel cards, not just NVIDIA.

OpenCode: Orchestration For Local Models

OpenCode is one possible orchestration layer for connecting a local model to an agent workflow.

What OpenCode adds around the model:

  • Connects to local model endpoints such as Ollama or vLLM
  • Provides tools for files, search, terminal commands, and code changes
  • Maintains task context and feeds tool results back to the model
  • Applies project instructions, skills, permissions, and workflows

Orchestration loop:

User request → LLM (reasoning) → Tool calls → Results → LLM → Next action
                ↑                                        |
                └────────── Loop until done ─────────────┘

Setting Up Ollama For Internal Network Access

By default, Ollama binds to localhost:11434. To make it accessible on your internal network:

Step 1: Configure Ollama to listen on all interfaces

Linux/macOS (systemd):

# Edit the systemd service
sudo systemctl edit ollama.service

# Add these lines:
[Service]
Environment="OLLAMA_HOST=0.0.0.0:11434"
Environment="OLLAMA_ORIGINS=*"

Windows:

# Set environment variables (System Properties → Environment Variables)
OLLAMA_HOST=0.0.0.0:11434
OLLAMA_ORIGINS=*
# Then restart Ollama from system tray

Setting Up Ollama - Firewall & Security

Step 2: Configure firewall

# Windows (PowerShell as Admin)
New-NetFirewallRule -DisplayName "Ollama" -Direction Inbound `
  -LocalPort 11434 -Protocol TCP -Action Allow

Alternative: Use a reverse proxy with authentication

# Example using Nginx with basic auth
# This adds security and allows HTTPS
⚠ Security note: Exposing Ollama without authentication on a network allows anyone to run models on your GPU. Always use a firewall or reverse proxy with auth in shared environments.

Summary

  • LLM ≠ Agent: An LLM generates text; an agent uses an LLM to accomplish tasks with tools and memory
  • Local deployment: Ollama (easiest), vLLM (fastest), ML Studio (Windows-native)
  • Agent orchestration: OpenCode bridges the gap between an LLM and an agent by adding tools, context, skills, and workflows
  • Network setup: External clients use http://10.93.0.226:11434/v1
Give it a try: connect OpenCode to the local Ollama Qwen3.6:35B model and explore what your private AI coding assistant can do.

Detailed MCP Server Setup

# Create the project
npm init -y
npm install @modelcontextprotocol/sdk zod

// server.mjs
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { readFile } from "node:fs/promises";
import { resolve, relative, isAbsolute, sep } from "node:path";
import { z } from "zod";

const ROOT = resolve(process.env.ALLOWED_ROOT ?? "./project");
const server = new McpServer({ name: "safe-filesystem", version: "1.0.0" });

server.registerTool("read_file", {
  description: "Read a UTF-8 text file inside the allowed project folder",
  inputSchema: { path: z.string().describe("Relative file path") }
}, async ({ path }) => {
  const file = resolve(ROOT, path);
  const rel = relative(ROOT, file);
  const outside = rel === ".." || rel.startsWith(`..${sep}`) || isAbsolute(rel);
  if (outside) throw new Error("Path is outside the allowed root");
  const text = await readFile(file, "utf8");
  return { content: [{ type: "text", text }] };
});

const transport = new StdioServerTransport();
await server.connect(transport);
